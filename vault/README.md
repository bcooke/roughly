# Roughly knowledge vault

Start with a topic map and follow links into focused notes. The vault is shared project knowledge: a contributor can read it on GitHub or open it as an Obsidian vault.

- [Product and methodology](topics/Product%20and%20Methodology.md): purpose, questions, interpretation, and participation.
- [Engineering](topics/Engineering.md): domain authority, reads, presentation, and technical decisions.
- [Contributing](topics/Contributing.md): work, review, documentation, and public/private boundaries.
- [Ideas and open questions](discovery/ideas/README.md): possibilities preserved without a commitment to build.
- [Project status](../PROJECT_STATUS.md): dated implementation state and active work.

Evergreen notes live at the vault root. `topics/` contains navigation maps; `discovery/` contains dated investigation and an `ideas/` parking lot; `decisions/` contains decision records; `delivery/` holds small task/context records when useful; `archive/` preserves historical proposals. [_meta/Documentation Guidelines](_meta/Documentation%20Guidelines.md) defines how these forms fit together.

Use relative Markdown links so the same links work in GitHub and Obsidian. [Obsidian supports Markdown internal links](https://obsidian.md/help/links) as well as wikilinks; an Obsidian-specific publishing service is not required.
